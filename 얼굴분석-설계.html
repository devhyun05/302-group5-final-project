얼굴 분석 — 측정·분석·컨설팅 설계

측정은 한 번, 소비는 여러 곳. 하나의 분석 파이프라인이 구조화된 FaceProfile을 만들고, 추천 자동화(룩 원탭 적용)와 분석 리포트가 이를 각자 소비한다. 기하·색은 온디바이스, 질감·지각·컨설팅은 AI — AI에게는 항상 사진과 함께 온디바이스 수치를 근거로 동봉한다.

§1

목적과 소비자

분석 결과의 소비자는 두 곳이며, 둘은 같은 프로필과 같은 해석 함수를 쓴다. 리포트에 "둥근형"이라 쓰고 추천은 각진형 컨투어를 주는 불일치가 구조적으로 불가능해야 한다.

  • 추천 자동화 — 분석 결과를 앱의 슬롯·축 파라미터(룩 트리)로 매핑해 원탭 적용. 이 앱만 가능한 차별점: 컨설팅 = 룩 추천 + 핏 시트 + 색·제품 추천(3채널) — 각자 원탭 적용.
  • 분석 리포트 — 측정·해석·컨설팅을 사용자에게 보여주는 화면. 여러 분석 기능이 각자 필요한 항목을 골라 노출한다(§9 노출 정책).

계층 모델 — 정의 기준

계층은 순서가 아니라 성격으로 나눈다. 판별법이 명확하면 항목이 섞이지 않는다.

계층정의판별법
L0 측정단위가 있는 숫자 하나"각도 −3°, 비율 1.08, Lab (72,8,18)"처럼 쓸 수 있으면 측정
L1 1차 분석측정들을 규칙으로 묶은 라벨임계값 표만 있으면 사람 없이 계산되는 것 — 얼굴형, 웜/쿨, 삼백안
L2 2차 분석전체를 보고 내리는 지각 판단문장이 "~해 보이는지", "~한 느낌"으로 끝나는 것 — 인상, 분위기, 퍼컬 세부톤
L3 컨설팅L1+L2에서 도출되는 처방"그래서 뭘 하라"가 들어있는 것 — 메이크업/헤어/패션

분담 원칙 (온디바이스 ↔ AI)

  • 기하(거리·각도·비율)와 색 수치는 온디바이스. 랜드마크와 픽셀 샘플링으로 계산. AI는 정밀 기하에 약하므로 숫자를 다시 추정하게 하지 않는다.
  • 질감과 지각 판단은 AI. 피부결·모공·인상 같은 게슈탈트는 비전 모델이 강하다. 단 질감은 성격상 "측정"이지만 담당은 AI다 — 온디바이스 CV로 만들기엔 비용이 크다.
  • AI에게는 항상 사진 + 온디바이스 수치를 동봉. AI는 숫자를 "읽고 해석"한다. 대표 사례: 실측 눈꼬리 각도(L0)를 주고 "보이는 인상의 눈꼬리는?"(L2)을 묻는다.
  • 모든 측정치에 confidence와 출처를 동봉. 조명 부족·샷 누락 시 해당 항목만 신뢰도 하향 또는 "미측정" — 틀린 값을 자신 있게 보여주지 않는다.
담당 표기: 온디바이스 랜드마크·픽셀 규칙 계산 · AI 비전 모델 · 하이브리드 수치 원료는 온디바이스, 판정은 AI 보조 · 깊이 TrueDepth/측면 있으면 수치, 없으면 AI 폴백(신뢰도 하향) · 드레이핑 AR 시뮬레이션 실험(§6)
§3

캡처 프로토콜

확정 — 최대 캡처 방침. 가이드 플로우로 전 샷을 요구하되 건너뛰기는 허용하고, 건너뛴 샷에 의존하는 항목은 리포트에 "미측정"으로 표시한다. 원본 샷·프로필·AI 응답은 전량 저장해 사용한다.
샷내용커버 항목
S1정면 무표정 (필수)기하·색·비대칭 전반 — 전체 항목의 대부분
S2정면 스마일 (필수)표정 섹션 전부, 웃을 때 비대칭·볼륨 변화, 치아·잇몸
S3/S4회전 스윕 (좌→우) — 확정측면 실루엣, 코 높이·비순각·E-line, 턱-목 연결, 거북목, 두상, 귀, 장단두
S5헤어 올린/넘긴 정면헤어라인, 이마 전체, 귀, 얼굴 외곽 실측
S6상반신 — 후면·타인 촬영목 길이·두께, 승모근, 얼굴 대비 목 비율
S7전신 (선택) — 후면·타인 촬영키 대비 얼굴 크기
확정 — 카메라 지정. S1~S5는 전면 고정: 실시간 게이트(거리·포즈·중앙)는 화면을 보며 맞춰야 성립하고, TrueDepth가 전면 전용이며, 전면은 단일 렌즈라 렌즈 선택 변수가 소멸한다. S6/S7은 후면 1x 메인 렌즈 고정 + 타인 촬영 안내: 가상 줌이 아닌 wide 물리 렌즈를 직접 지정하고 배율·초점거리를 기록, 초광각(0.5x) 감지 시 재촬영 안내. 크로스샷 규칙 — 정밀 기하는 조건 고정된 전면 샷에서만 측정하고, 신체 샷에서는 같은 프레임 내 비율만 산출한다(분자·분모가 같은 왜곡을 받아 상쇄, §7).
  • 품질 게이트(메타 항목) — 조명 밝기·색편향, 포즈 각도(정면 ±10°), 얼굴 크기/해상도, 가림(안경·앞머리·수염) 검출, 거리 게이트(얼굴 크기 밴드로 촬영 거리를 고정 — 원근 왜곡 통제, §7), 중앙 배치(렌즈 왜곡이 심한 프레임 가장자리 회피). 미통과 시 재촬영 안내가 UX의 일부. 게이트 결과는 이후 전 항목 confidence의 입력이 된다.
  • 프레임 집계 — 각 샷은 단일 프레임이 아니라 게이트 통과 프레임 ~30장의 중앙값으로 측정(랜드마크 노이즈 억제).
  • 측면 캡처 = 회전 스윕 (확정) — 정지 측면 샷은 고개를 돌리면 화면이 안 보여 게이트를 맞출 수 없다. "정면을 본 상태에서 천천히 좌→우로" 스윕하며 프레임별 yaw(랜드마크 변환 행렬)로 각도 버킷(15°·30°·45°·60°)별 최적 프레임을 자동 선별. 캡처 플로우는 "정면→스윕→스마일" 하나로 이어진다.
  • 스윕 품질 검출 — 전부 온디바이스: 회전 속도 = yaw 프레임 간 변화율, 눈 감김 = 블렌드셰이프(eyeBlink)/EAR, 모션 블러 = 얼굴 크롭 라플라시안 분산. 미달 구간만 재시도 안내.
  • 스윕 리스크 노트 — 진짜 측면(±90°)은 추적이 끊긴다. 얼굴 검출은 yaw ~60–75°를 넘으면 랜드마크를 놓친다. 폴백: ① TrueDepth 기기는 측면이 아예 불필요 — 정면 3D 메시에서 프로파일 곡선을 직접 산출(스윕은 검증 보조) ② 비-depth 기기는 추적 가능 최대 각도까지 수치 측정 + 추적 끊김 전후 원시 프레임 저장(회전 속도 외삽으로 ~90° 추정) → 해당 프레임의 측면 계측은 AI 시각 판단 + confidence 하향.
  • 타인 촬영 가이드(S6/S7) = 촬영자 모드 + 자동 셔터 (확정) — 촬영자는 앱을 처음 보는 사람이라는 전제. 실루엣 오버레이(상반신/전신 프레임) + 거리·수평 게이지를 띄우고, 게이트 통과 시 3초 카운트다운 자동 촬영. 촬영자에게 어떤 조작도 요구하지 않는다.

§5

항목 간 관계 노트

중복 통합과 "관련은 있으나 별개" 판정의 기록. 논의에서 정정된 것 포함.

1. 대비감 — 측정 1, 소비 3

퍼컬의 "대비감", 피부의 "피부 대비감", 눈의 "눈동자–피부 대비"는 하나의 측정(부위 간 명도차 행렬)을 세 곳에서 소비하는 것. 측정 항목은 F의 대비 행렬 하나만 둔다.

2. 피부 4항목은 전부 별개 — 정정 반영

유분/광 분포(공간 맵) · 광택 타입(질) · 모공(크기·모양·분포) · 탄력 — 네 가지는 각각 독립 항목으로 유지한다. 실제 중복은 원목록에서 '모공' 표기가 2회였던 것뿐.

3. 눈밑 존 — 측정은 분리, 해석은 통합

다크서클 색값(L0-F)과 구조(애교살/지방/꺼짐 — G·L2)는 별개로 측정하고, "눈밑 존 통합 해석"(L2) 한 항목에서 겹침을 판정한다. 눈밑 탄력감도 이 해석에 포함.

4. 인중 — 4개 항목 각각 독립 — 정정 반영

인중 길이(L0-C) · 코-인중 비율(L1) · 인중 깊이감=또렷함(L0-G) · 하관 입체감(별개 축) — 전부 별개 항목. 단 용어는 통일한다: "깊이감"과 "입체감"은 같은 개념이므로 문서·스키마에서 "입체감"으로 표기.

5. 실제 중복 (동일 항목 2회 표기)

턱선 선명도 = 턱선 흐림 정도 · 입가 살 처짐 = 입가 처짐 · 윤곽선 흐림/또렷 = 외곽선 강도 — 각각 1개 항목으로 통합.

6. 무게중심 2종 — 별개 — 정정 반영

지각 무게중심(L2 인상): 색·모양·크기·비례를 합산해 어디가 가장 눈에 띄는가 — 존재감 분포. 볼륨 하강(L2 볼륨축): 볼륨의 물리적 상/하 위치. 이름이 비슷할 뿐 측정도 소비도 다른 별개 항목.

7. 측면 축 — 의존 관계이지 중복이 아님 — 정정 반영

비순각(L0)은 입 돌출·코끝 들림 등의 결과로 변하는 실측 각도이고, 측면 실루엣(L2)은 비순각을 포함한 이마–코–입–턱 프로파일 전체의 상위 종합. 셋 다 각자 측정·판정하되 스키마에 의존 관계(derivedFrom)를 명시해 컨설팅이 원인 항목을 짚을 수 있게 한다.

8. 눈 3항목 — 별개 — 정정 반영

눈꺼풀 지방량(G — 구조) · 홍채 상하 노출률=눈동자 노출 정도(A — 뜨는 힘) · 눈 개구 대비 홍채 비율=눈동자 비율(A — 흰자 대비 크기)은 서로 다른 세 측정. "눈꺼풀 무게감"(L2)은 이 셋을 근거로 한 별도의 종합 인상 항목.

9. 장단두형 ⊂ 두상

장단두형(L1)은 두상 곡률 계측(G)의 파생 라벨. 측정은 두상 하나, 라벨은 별도.

§6

드레이핑 시뮬레이션 — 세 번째 분석 수단

퍼스널컬러의 민감도 축(명도/채도/청탁/색상/색온도) 체크는 관찰이 아니라 실험이다 — 색을 대보고 반응을 봐야 한다. 이 앱은 AR로 색을 실제로 입힐 수 있으므로 디지털 드레이핑이 가능하며, 이는 관찰(사진)·계측(랜드마크)에 이은 세 번째 분석 수단이다.

  1. 축별 대비 색 페어를 자동 구성 — 예: 웜골드 vs 쿨실버 톤베이스, 청귤 vs 탁로즈 립, 고명도 vs 저명도.
  2. 동일 프레임에 페어를 번갈아 렌더링해 캡처 (조명·포즈 고정 — 페어 간 조건 차이 제거).
  3. 판정: AI 비전에게 페어 비교를 시키거나(얼굴빛·잡티 부각·경계 뜸 기준), 사용자에게 고르게 하거나, 둘 다(교차 검증).
  4. 결과가 퍼컬 최종 판정(L2)의 근거로 들어간다 — "여름 뮤트: 저채도 반응 우세(드레이핑 5/6 라운드)" 식으로 근거 추적 가능.
§7

절대 스케일 · 왜곡 보정 · 3D 전략

기하 측정(L0)의 정확도는 두 가지 왜곡 통제에 달려 있다. 렌즈 왜곡과 원근 왜곡은 원인도 보정법도 다른 별개 문제다.

0-a. 렌즈 왜곡 (광학) — 인트린식 기반 언디스토트

전면 카메라는 광각이라 배럴 왜곡이 있고 프레임 가장자리로 갈수록 심해진다. 후면 메인 렌즈는 덜하지만 0이 아니다. 보정: ARKit/ARCore가 제공하는 카메라 인트린식·왜곡 계수로 측정용 프레임을 언디스토트한 뒤 랜드마크·샘플링을 수행 (또는 랜드마크 좌표를 역보정). 게이트의 중앙 배치 조건이 잔여 왜곡을 최소화한다. 카메라·렌즈별로 보정 프로파일이 다르므로 샷마다 카메라·렌즈·배율을 기록한다(§3 카메라 지정 정책). 안드로이드는 인트린식 제공이 기기마다 달라(Camera2 지원 기기 한정) 미제공 기기는 언디스토트 생략 + 기하 그룹 confidence 하향으로 폴백.

0-b. 원근 왜곡 (거리) — 더 치명적인 쪽

셀피 거리 ~30cm에서는 코가 크게, 귀·얼굴 외곽이 좁게 투영된다 — 렌즈가 아니라 거리의 문제라 언디스토트로 잡히지 않는다. 코 폭·코 길이·얼굴 폭/길이비 등 L0 기하가 촬영 거리마다 다르게 측정되는 원인. 보정 3단: ① 캡처 시 거리 게이트(얼굴 크기 밴드)로 거리 자체를 고정 ② 거리 추정(TrueDepth 직접, 또는 홍채 스케일+초점거리)값을 기록해 잔여 왜곡을 수치 보정 ③ TrueDepth 기기는 아예 3D 메시에서 직접 측정 — 미터 단위 3D 공간이라 원근·렌즈 왜곡을 모두 우회한다. "지난 분석과 비교"는 카메라·거리 조건이 같거나 정규화된 프로필끼리만 유효.

1. 홍채 스케일 — 전 기기, 절대 크기(mm)

홍채는 측정 대상이 아니라 자(ruler)다. 사람 홍채 가로 지름은 ~11.7mm(개인차 ±0.5mm)로 거의 상수 — 동공은 조명 따라 변하므로 부적합, 홍채가 기준. MediaPipe 478포인트의 홍채 랜드마크(469–478)로 mm/px 스케일을 잡으면 추가 하드웨어 없이 전 측정치를 절대 단위로 환산. 오차 ~4–5%로 리포트 용도에 충분.

2. TrueDepth — 지원 기기, 진짜 입체 계측

FaceID 아이폰은 전면 TrueDepth로 ARKit이 미터 단위 3D 얼굴 메시를 제공 — G 그룹(코 높이, 광대 돌출, 볼륨맵 등)이 전부 실수치가 된다. 프로젝트의 ARKitDepthSource 경로를 살려 연결. MediaPipe의 z는 상대값이라 절대 계측엔 부족하지만 좌우 비교(비대칭)에는 그대로 사용.

3. 회전 스윕 — 측면 프로파일 재구성 (확정, §3)

고개를 천천히 좌→우로 돌리는 동안 멀티프레임 캡처로 측면 프로파일을 재구성 — 정지 측면 샷을 대체하는 확정 방식. yaw ~60–75° 초과는 추적이 끊기므로 §3 스윕 리스크 노트의 폴백(depth 기기 = 정면 메시 직접 산출, 비-depth = AI 보조 + confidence 하향)을 따른다.

3단 폴백: 홍채 스케일(전 기기, 절대 크기) → TrueDepth(지원 기기, 입체 계측) → 미지원 기기는 입체 항목만 AI 시각 판단 폴백(confidence 하향 + 리포트에 "추정" 표기).

§8

Confidence 정책

  • 모든 측정치는 {value, unit, confidence, source, shots} 봉투로 저장. source는 landmark | pixel | depth | ai | draping.
  • 품질 게이트 결과(조명·포즈·해상도·가림)가 그룹별 confidence의 기본 입력 — 예: 조명 색편향 감지 시 색 그룹(F)만 하향.
  • confidence가 임계 미만이면: 리포트는 "측정 보류(사유)" 표시, 추천 엔진은 해당 항목을 건너뜀. 두 소비자가 같은 규칙으로 저품질 데이터를 처리한다.
  • 샷 누락 의존 항목은 unmeasured — 값 없음과 신뢰도 낮음을 구분.
§9

민감 항목 노출 정책

확정 — 측정·저장은 전 항목 수행. 개발 모드에서는 전부 노출, 출시 모드에서는 민감도 태그 기반 필터링. 기능별 노출 수위는 개발·QA 과정에서 조정한다 — 분석 기능이 여러 개이므로 기능마다 노출 매트릭스가 다르다.
태그의미예시
무표기자유 노출얼굴형, 눈매, 퍼스널컬러, 대비 타입
민1노출 가능하되 표현 조정 (컨설팅 톤)눈 높이 좌우차, 다크서클, 잇몸 노출, 턱선 선명도
민2기본 비노출 — 기능별 판단으로 개방비대칭 좌우차 세트, 볼륨 하강, 이중턱, 탄력, 안구 돌출
민3내부 전용 — 컨설팅 근거로만, 직접 노출 금지비대칭 종합 스코어, 황금비 편차
  • 필터는 L2→L3 경계와 리포트 렌더 직전 두 곳에서 적용 — 분석은 정직하게, 문구는 컨설팅 톤으로.
  • 노출 매트릭스는 기능 × 태그 → 노출 수위 설정 테이블로 관리 (기능별 오버라이드 허용). 개발 모드 토글은 이 매트릭스를 전면 무시.
  • 시작 기본값 (확정 — QA에서 기능별 조정): 퍼스널컬러 기능 = 민0만 · 메이크업 추천 = 민1까지(근거 문구는 컨설팅 톤 변환 후) · 종합 리포트 = 민1 기본 + 민2는 "자세히 보기" 옵트인 토글 · 민3은 어디서도 비노출.
  • 시술을 연상시키는 표현은 태그와 무관하게 L3 문구 가이드라인에서 별도 통제.
§10

FaceProfile 스키마 초안

interface MetricEnvelope<T> {
  value: T;
  unit?: 'mm' | 'deg' | 'ratio' | 'lab' | 'score';
  confidence: number;              // 0..1
  source: 'landmark' | 'pixel' | 'depth' | 'ai' | 'draping';
  shots: ShotId[];                 // ['S1'] 등 — 근거 샷
  sensitivity: 0 | 1 | 2 | 3;      // §9 태그
  derivedFrom?: MetricKey[];       // §5-7 의존 관계
}

interface FaceProfile {
  version: 2;
  capturedAt: string;
  capture: {                        // §3
    shots: Record<ShotId, { taken: boolean; frames: number;
            camera: 'front' | 'rear';              // §3 카메라 지정 정책
            lens: 'front' | 'wide'; zoomFactor: number }>;
    gate: { lighting: number; pose: number; distance: number; centered: boolean;
            occlusion: string[] };
    cameras: Partial<Record<'front' | 'rear',
              { intrinsics?: Intrinsics; undistorted: boolean }>>; // §7-0a
    distanceMm: number | null;                     // §7-0b 얼굴 샷 기준 거리
    scale: { mmPerPx: number | null; method: 'iris' | 'truedepth' | null };
  };
  geometry:  Record<MetricKey, MetricEnvelope<number>>;   // L0 A~E
  color:     Record<MetricKey, MetricEnvelope<Lab | number>>; // L0 F
  depth?:    Record<MetricKey, MetricEnvelope<number>>;   // L0 G (조건부)
  dynamics?: Record<MetricKey, MetricEnvelope<number>>;   // L0 H (S2)
  body?:     Record<MetricKey, MetricEnvelope<number>>;   // L0 I
  derived:   Record<MetricKey, MetricEnvelope<string>>;   // L1 라벨
  perception?: Record<MetricKey, MetricEnvelope<string>>; // L2 (AI 구조화 출력)
  personalColor?: { season: string; sub: string; border?: string;
                    axes: Record<Axis, MetricEnvelope<string>> }; // §6 근거 포함
  consulting?: {                    // L3
    makeupFit: FitSheet;            // 부위/역할 셀렉터 공간 델타 (§5)
    makeupProducts: ProductRec[];   // 색·제품 추천 — 핏이 못 만지는 영역(립색·컨실러·파우더존·미백…)
    makeupLook: LookRef;            // 룩(모양) 추천 참조
    makeupRationale: Record<SlotKey, string>;
    hair: string[]; fashion: string[]; photoTips: string[];
  };
}
  • 브리지: { type: 'analyzeFace', shots: [...] } (RN→Unity) / { type: 'faceAnalyzed', profile } (Unity→RN) 추가.
  • AI 호출 (확정 — 3단 분리 호출): ① 질감·외관(사진 위주) → ② 인상 종합+퍼컬(① 결과+수치 동봉) → ③ 컨설팅(①② 결과). 단일 거대 호출 금지 — 출력 스키마가 뭉치면 품질이 떨어지고, 분리해야 부분 재분석이 성립한다(드레이핑 후 퍼컬만 재판정, 취향 변경 시 컨설팅만 재생성). 각 단계는 구조화 출력(스키마 강제), 산문 응답 금지.
  • AI 비용 정책 (확정): 사진은 1회 업로드 후 file 참조 재사용 · 프로필 캐시, 명시적 재분석 요청 시에만 재호출 · 모델은 단계별 티어링(질감 태깅 = 저비용 티어, 인상·컨설팅 = 상위 티어 — 구체 모델·비용 측정은 P3 착수 시).
  • 저장: 원본 샷 + 프로필 + AI 원응답 전량 보관 — "지난 분석과 비교" 리포트, 저장 룩의 톤 태그로 확장.
