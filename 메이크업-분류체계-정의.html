메이크업 분류체계 — 레인 × 슬롯 × 세부부위 × 레이어

메이크업 시스템의 계층·용어·순서 규칙의 단일 기준 문서. 코드 추출(src/composer/·브리지·목업·테스트 7방향 조사)로 현행 구현과 대조해 확정했다. 부위별 상세 스펙은 메이크업-부위-카탈로그.html, 트리 UI 동작은 메이크업-컴포저-목업-v2.html이 담당하고, 이 문서는 그 둘이 공유하는 뼈대와 낱말만 못박는다.

§0한눈에 — 계층 전체

저장물 3종 — 레인별 분리 저장: 내 룩(메이크업: 트리+mkGain) · 내 보정(FIT: 워프값) · 내 핏 ★신설(공간 델타 시트 — §5) — 각자 저장·각자 적용
'스타일'(레인 횡단 한 벌)은 장래 개념 — 헤어·패션 레인이 생기고 묶음의 자리가 정해지면 도입
├─ 메이크업 레인 — 색소를 얹는다 (룩 트리가 소유)
│   └─ 슬롯 8종 (대분류): 피부 · 컨투어 · 눈썹 · 눈 · 렌즈★승격 · 립 · 헤어 · 데코
│       └─ 세부부위 (중분류, RegionKey 33종+신설): 제품을 바르는 자리이자 제품 종류
│            └─ 레이어 스택 (소분류, 잎 ProductLeaf): 제품×적용×농도의 1회 도포, 여러 겹 가능
└─ 보정(FIT) 레인 — 지오메트리를 바꾼다 (얼굴형 워프, 룩 트리 밖·절대 안 섞임)

각 세부부위에 걸리는 편집 축 6종(계층 아님, 직교 탭): 모양 · 텍스처 · 색 · 마감 · 농도 · 핏 — 핏 값의 소유는 §5 시트 캐스케이드(탭은 편집 표면)

‘전체’는 계층이 아니라 스코프 선택자 — UI 개념으로만 존재하고 분류 트리에는 없다. 농도는 3층: 겹 농도(잎별 opacity) × 레인 게인(메이크업 mkGain/보정 wpGain, 각각 저장) — ‘전역’은 앱 전체 하나가 아니라 레인 전체에 곱해진다는 뜻.

§1확정 규칙

R1

대분류 = 슬롯 8종. 피부 · 컨투어 · 눈썹 · 눈 · 렌즈 · 립 · 헤어 · 데코. 슬롯은 해부학적 부위가 아니라 작업 도메인이다(컨투어는 뺨·코·턱에 걸치고, 데코는 자유 좌표).

R2

중분류 = 세부부위. 슬롯 안에서 “제품 종류 = 세부부위”(예: 눈썹 슬롯의 지우개/결/채움/한올/라이트너/스타일). 피부처럼 효과 축으로 읽히는 것(톤·결·균일함·커버·마무리)도 동일한 세부부위이며, 노출되는 편집 축이 적을 뿐이다(퇴화 케이스).

R3

소분류 = 레이어(잎). 한 세부부위에 여러 겹을 쌓을 수 있고, 각 겹은 제품(색 채널·제형·마감 — §5) × 테크닉(모양·프로파일·강도 — 구 ‘적용 속성’) × 농도의 1회 도포다. 농도는 크로스커팅 축(레인 게인과 곱연산)이되 §5에서 제품 1회농도×테크닉 강도로 분해된다. 핏은 레이어가 소유하지 않는다 — 값은 핏 시트 캐스케이드에서 계산돼 겹에 적용된다(§5, 07-11 개정).

R4

트리의 순서는 바르는 순서다 — 하단이 가장 먼저. 데이터로는 kids[0]·layers[0] = 먼저 바른 것 = 합성 최하단(현행 그대로, painter's algorithm). 화면 표시만 반전해 목록 맨 아래 = 먼저 바른 것으로 보여준다(레이어 패널 관례). 물리 제약이 있는 곳만 순서를 강제한다(렌즈 베이스<내부<림).

R5

룩 = 조합의 명명 스냅샷. 분류(슬롯·세부부위)는 앱이 정의하는 고정 스키마이고, 룩은 그 슬롯들을 채운 레이어 스택 인스턴스에 이름을 붙인 것이다. 트리의 어느 층이든(부위 룩·세부 룩) ☆승격으로 라이브러리에 등록할 수 있다. copy-on-write 3규칙(편집 중 무질문 / 시스템 프리셋 불변 / 중간 계층 기본 익명 흡수)을 따른다.

R6

제품↔부위는 다대다. 한 제품은 여러 세부부위에(립앤치크 — 색·마감·농도 3축만 번역되고 모양·핏은 부위 고유), 한 세부부위엔 여러 제품·여러 모양을 겹으로 덧바를 수 있다(＋겹).

§4레이어(잎) 스키마

소분류 한 겹의 정의. 현행 ProductLeaf/축 컨트롤과 정렬된 개념 스키마 — 필드명은 현행 브리지 필드(부위별 *Color·*Finish…)를 그대로 쓰고, 이 구조는 낱말의 소속을 못박는 용도다.

// 레이어 = 제품 × 적용 × 농도 — 한 세부부위 스택 안의 한 겹
Layer {
  region: RegionKey            // 어느 세부부위에
  product: {                   // 무엇을 —— 제품 속성
    color:   hex | {stopA, stopB, gradient}   // 색 (그라데 스톱 포함)
    texture: 제형 enum | 그림 임포트            // 텍스처: 파우더/리퀴드/젤/펜슬… 또는 컬러 아트
    finish:  enum(0=새틴 기준) + FinishBundle?  // 마감(광): 매트·새틴·글로시·시머/펄 + 커스텀 5축
  }
  technique: {               // 어디에·어떤 형태로 —— 테크닉 (구 ‘적용 속성’, 해부는 §5)
    shape: 실루엣 프리셋 | 존 선택 | 마스크 임포트  // 모양 (부위마다 실현이 다름 — §6 용어 규약)
    gradient · edge · strength                 // 프로파일·강도 — §5에서 정의
  }
  // 핏: 레이어 소유 아님(07-11 개정) — 핏 시트 캐스케이드의 computed 값이 겹에 적용(§5).
  //     골드 슬라이더(배수=1·오프셋=±0 기준)는 그 시트를 쓰는 편집 표면.
  opacity: 0..1              // 농도 — 메이크업 레인 게인(mkGain)과 곱연산. §5에서 coverage×strength로 분해
  visible: bool                // 눈 아이콘 — 꺼진 겹은 컴파일 제외
}

스택 = Layer[]                 // index 0 = 먼저 바름 = 합성 최하단
트리 전체가 같은 규약           // flattenTree가 DFS로 눌러 펴 순서 그대로 셰이더 합성(ov0→ov3)
표시는 반전                    // 화면 맨 아래 행 = index 0 (A1 구현 완료 — §7)

‘제품’은 현행 코드에 1급 타입이 없다(productName은 표시용 라벨). 멀티유즈(R6)는 제품 개체 공유가 아니라 색·마감·농도 3축 번역(multiUse.ts)으로 구현. 07-11 개정: 제품 만들기·시중품 프리셋 도입에 따라 §5에서 1급 엔티티로 승격(A12) — 이 문단의 ‘비개체화’ 방침은 §5가 대체한다.

§5레이어 해부 — 제품 × 테크닉, 핏은 시트

§4 골격을 한 층 더 파고든 해부(2026-07-11 확정). 세 낱말의 소속: 제품=물감(그 물건이 무엇인가) · 테크닉=붓질(그걸로 무엇을 하는가) · 핏=나에게 맞춤(내 얼굴 어디에·어떻게 틀어서). 각 필드에 현 엔진 표현 가능 여부 주석(✅ 현행 / 🟡 부분·근사 / ❌ 신규 — 07-11 셰이더 감사 기준).

모양 vs 핏 — 재정의 (07-11)

  • 모양 = 룩이 들고 다니는 규칙 전체. 형태 프리셋만이 아니라 랜드마크 앵커링 룰까지 — “윙업이고, 윙은 눈꼬리점에서 시작해 눈 길이의 30%”는 통째로 모양. 누구 얼굴에 얹어도 같은 방식으로 해석되는 함수 모양(랜드마크) → 배치. 랜드마크에 맞추는 것 자체는 모양이 하는 일이다.
  • 핏 = 그 규칙 위에 얹는 개인 편차(델타). 출처가 AI 분석(“하관 처짐 → 블러셔 +y”)이든 손 드래그든 수치 조정이든 같은 채널. 광대에 붙는 건 룰(모양), 광대보다 올리는 건 델타(핏). 델타 0 = 룩 그대로(Finish 0=새틴과 같은 baseline 규약).
  • 핏이 만질 수 있는 건 공간뿐 — 배치·분포·룰 델타. 색·제품·마감·농도는 절대 못 만진다(룩의 정체성). 이 선이 없으면 핏이 제2의 룩으로 비대해져 모양/핏 구분이 무의미해진다.
