# iOS App Store Readiness Checklist

이 문서는 AURA iOS 앱을 App Store 심사에 제출하기 전 확인해야 하는 항목을 정리합니다.
현재 브랜치의 목표는 로그인 없이 얼굴 촬영, OpenAI 기반 AI 분석, 추천 결과 확인 플로우를 심사자가 안정적으로 확인할 수 있게 만드는 것입니다.

## 이번 브랜치에서 정리한 항목

- 로그인 없이 사용할 수 있도록 로그인 화면에 `게스트로 시작하기` 진입을 추가했습니다.
- 하단 촬영 버튼과 홈 얼굴 진단 흐름을 얼굴 촬영 및 AI 분석 플로우로 연결했습니다.
- 사용자 화면에서 사용하지 않는 실시간 필터 진입 버튼을 제거하고, 분석 결과 CTA를 `추천 제품 보기`로 변경했습니다.
- 카메라 권한 거부 시 한국어 안내와 설정 이동 버튼이 보이도록 정리했습니다.
- 카메라/사진 권한 문구를 얼굴 촬영과 AI 메이크업 분석 목적에 맞게 수정했습니다.
- 촬영 이미지 업로드가 실패해도 로컬 이미지 URI로 분석 로딩/결과 화면이 계속 열리도록 fallback을 추가했습니다.
- 촬영한 사진이 분석 로딩 화면과 분석 결과 상단 이미지에 우선 표시되도록 연결했습니다.
- 한 사용자 기준 얼굴 분석 기능을 최대 2회까지 사용할 수 있도록 기기 내 카운터를 추가했습니다.
- 앱 내부에서 개인정보 처리방침 화면에 접근할 수 있도록 추가했습니다.
- `준비중`, `데모`, `테스트`처럼 심사 품질에 좋지 않은 사용자 노출 문구를 정리했습니다.

## 제출 전 필수 확인

- 실제 iPhone에서 앱 실행 후 아래 흐름이 크래시 없이 이어지는지 확인합니다.
  - 앱 실행
  - 게스트로 시작하기
  - 튜토리얼
  - 얼굴 촬영
  - AI 분석 로딩
  - 분석 결과
  - 추천 제품 또는 홈 복귀
- 카메라 권한 거부 시 앱이 멈추지 않고 안내가 보이는지 확인합니다.
- 사진 보관함 권한 거부 시 앱이 멈추지 않고 안내가 보이는지 확인합니다.
- 백엔드 서버 또는 OpenAI 분석 API가 응답하지 않아도 핵심 화면 플로우가 fallback으로 진행되는지 확인합니다.
- 앱 화면에 `localhost`, API URL, JSON, debug text, 개발 로그 문구가 보이지 않는지 확인합니다.
- App Store Connect의 Privacy Label 입력 내용이 실제 코드 동작과 일치하는지 확인합니다.
- Xcode Archive 또는 EAS Build 결과에서 Privacy Manifest, Required Reason API 관련 warning이 없는지 확인합니다.

## 확인 필요

- 운영 백엔드에서 얼굴 이미지가 OpenAI API 또는 다른 분석 API로 전송되는 정확한 시점과 보관 기간을 확정해야 합니다.
- 얼굴 원본 이미지 삭제 정책과 사용자 삭제 요청 처리 방식을 백엔드 문서와 개인정보 처리방침에 맞춰야 합니다.
- 실제 App Store 제출 전 문의 이메일, 지원 URL, 개인정보 처리방침 URL을 실제 운영 주소로 교체해야 합니다.
- 분석 횟수 2회 제한을 서버 사용자 기준으로 관리할지, 현재처럼 기기 기준으로 관리할지 확정해야 합니다.
- 프로덕션 빌드에서 사용하지 않는 필터 관련 딥링크와 라우트 등록을 제거할지 결정해야 합니다.

## OpenAI API 사용 원칙

- React Native 앱에 OpenAI API key를 직접 넣지 않습니다.
- 앱은 촬영 이미지 또는 분석 요청을 백엔드로 전달하고, 백엔드가 OpenAI API를 호출합니다.
- 백엔드 요청 실패 시 앱은 mock 또는 로컬 fallback으로 크래시 없이 동작해야 합니다.
- 얼굴 이미지와 분석 결과는 광고, 마케팅, 사용자 추적, 데이터 마이닝 목적으로 사용하지 않습니다.
