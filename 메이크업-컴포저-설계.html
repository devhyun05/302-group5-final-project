00

멘탈 모델 — 레이어 × 축 × 워프

컴포저의 모든 화면은 세 개념 위에 선다. 레이어(스택 위의 한 장), 레이어가 가진 5개 축(대상·모양·텍스처·색·마감·농도를 각각 독립 선택 — R5), 그리고 랜드마크에서 뜬 메시를 손으로 미는 워프 핸들(R7). 목업은 이 세 층위를 시각적으로 항상 구분해야 한다: 제품 조작은 로즈, 워프/핏 조작은 골드.

AXIS 01 · TARGET

대상 / 범위

어느 부위에 올릴지. 전용 부위(립·눈·눈썹·볼) + 자유 배치(얼굴 어디든 — R1).

→ 전용 메시 or 캐노니컬 데칼로 자동 분기 (R6)
AXIS 02 · SHAPE

모양 / 적용범위

메시 프리셋(윙업·퍼피·롱) 또는 자유 마스크. 얼마나 넓게 덮는지.

→ eyelinerStyle · 브러시 반경
AXIS 03 · TEXTURE

텍스처

매트·글리터·그라데·패턴 프리셋, 또는 내 그림 임포트(R9).

→ setLipStyle/setFaceOverlay 등
AXIS 04 · COLOR

색 / 그라데

단색 스와치 + 커스텀 피커, 2색 그라데이션 스톱(R2).

→ lipColor · 그라데 스톱 A/B
AXIS 05 · FINISH

마감

매트 · 새틴 · 글로시 · 시머. 반사·글리터 게인.

→ 셰이더 finish 파라미터
AXIS 06 · OPACITY

농도

레이어별 강도 0–100. 전역 농도와 곱해짐.

→ *Intensity
주의

기존 FilterParams의 부위별 *Intensity/*Color는 레이어 하나의 축 값으로 재해석된다. 컴포저는 이 플랫 구조 위에 레이어 배열을 얹고, 저장 시 각 레이어를 순서대로 브리지 메시지로 방출한다 — 브리지 프로토콜 자체는 확장만 하고 갈아엎지 않는다.

01

홈 화면 — 초보자 진입점

앱을 열면 지금과 똑같이 보인다: 카메라 프리뷰 위 프리셋 칩. 초보자는 여기서 끝나도 된다. 칩 하나를 고르면 룩이 입혀지고 셔터를 누른다. 고급 경로로 가는 문은 딱 하나 — 프리셋 칩 줄 오른쪽 끝의 ＋ 만들기 칩, 그리고 조정 패널 상단의 "레이어로 편집" 토글.

신규＋ 만들기 칩

캐러셀 맨 끝. 로즈 아웃라인 칩. 탭하면 컴포저 시트(섹션 02)가 아래에서 올라온다. 현재 프리셋을 레이어들로 분해해 시드로 얹는다 — 빈 캔버스가 아니라 "내추럴을 뜯어보기".

유지전역 농도 바 · 셔터 · 카메라

농도 바·셔터·전/후면 전환은 위치·동작 불변. 프리뷰 꾹누름 → 쌩얼 비교 제스처도 유지.

  • 조정 버튼: 지금은 부위 탭 패널을 열지만, 이제 그 패널 상단에 레이어로 편집 토글이 붙는다.
02

컴포저 시트 — 레이어 스택 (R8)

＋만들기를 누르면 하단 시트가 프리뷰의 절반 높이까지 올라온다. 최상단은 레이어 목록 — 스택 순서(위=앞). 각 행은 드래그 그립·썸네일·이름·눈(켜기)·… 오버플로. 목록 위 스텝 헤더에 스타일 이름과 저장 버튼. 목록 아래로 축 편집기(섹션 03)가 이어진다 — 선택된 레이어 하나를 편집.

신규레이어 행

  • ⣿ 그립 — 롱프레스 후 드래그로 순서 변경. 놓으면 스택 재정렬 + 즉시 재합성.
  • 썸네일 — 색/텍스처 미리보기(원형). 그라데면 두 색, 내 그림이면 이미지 축소.
  • 이름 — 자동 생성(대상+모양), 탭해서 개명.
  • ◉ 눈 — 켜기/끄기. 끈 레이어는 흐리게. 합성엔 빠지되 삭제 아님.
  • 행 탭 — 선택(로즈 하이라이트) → 아래 축 편집기가 이 레이어를 로드.
  • 스와이프 좌 or … 메뉴 — 복제 · 삭제.

＋ 레이어 추가대상 선택 팝오버

탭하면 대상 그리드가 뜬다: 립 · 아이라인 · 눈썹 · 블러셔 · 아이섀도(전용 메시) / 자유 배치(얼굴 위 아무 곳 — 캐노니컬, R1). 고르면 기본 축 값의 새 레이어가 스택 맨 위에 추가되고 편집기가 열린다.

합성 순서전용 메시 위에 캐노니컬 (R6)

목록 순서 = 그리기 순서. 전용 메시 레이어(칼선 정밀)와 캐노니컬 데칼 레이어가 한 스택에 섞여 존재. 렌더러는 레이어 타입에 따라 LipStyleRenderer 등 전용 경로 or _MakeupOverlay 데칼로 자동 분기.

경로 A화면 위 드래그 핸들

얼굴의 제어점에 골드 도트. 직접 끌어서 offset 편집 — 눈꼬리를 눈 라인 밖으로 당겨 눈 커보이게, 오버립으로 입술 라인 넘기기, 눈썹 아치 정점 올리기. 놓으면 실시간 재합성. 자연스러운 만큼만 이동하도록 클램프 범위 표시(연한 골드 반경).

경로 B정밀 슬라이더

같은 offset을 하단 골드 슬라이더로. 부위별 명명된 축: 눈꼬리 바깥/올림 · 윙 길이 · 오버립 · 아치 높이. 손 안 떨리게 미세 조정. 기존 browThickness·browArch가 이 체계의 첫 두 슬라이더 — 이미 있는 워프 맛보기를 일반화.

기존 UI와의 통합 — 대체가 아니라 승격

지금 화면을 버리지 않는다. 초보자가 보는 표면은 거의 그대로 두고, 그 아래에 컴포저를 추가 레이어로 깐다. 왼쪽이 오늘, 오른쪽이 승격 후.

오늘 (프리셋 앱)

  • 부위 탭 (피부·립·볼·눈·눈썹·보정)
  • 부위마다 슬라이더 + 스와치 나열
  • 프리셋 칩 = 통짜 FilterParams
  • 전역 농도 = 모든 강도에 일괄 곱
  • 내 그림 임포트 = "보정" 탭 구석
→

승격 후 (컴포저)

  • 부위 탭 → 축 탭 (한 레이어의 6축)
  • 슬라이더 나열 → 레이어 스택 + 축 편집기
  • 프리셋 = 레이어 배열의 프리팹 (＋만들기로 분해)
  • 전역 농도 바 = 그대로 (스택 최상위 곱)
  • 내 그림 = 텍스처 축 1급 시민 + 자유 배치
1

프리셋 탭

초보자. 칩 하나 → 셔터. 컴포저 존재도 모른 채 완결.

2

농도로 톤 조절

전역 농도 바로 강약. 아직 한 슬라이더.

3

＋만들기로 분해

마음에 든 프리셋을 뜯어 레이어로. 색·모양만 살짝 바꿔보기.

4

워프·내 그림·저장

핏 조정, 그림 임포트, 자유 배치, 내 스타일로 저장. 고급 완주.

핵심

하나의 UI 안에서 난이도가 점증한다. 어떤 화면도 초보자에게 레이어·워프를 강요하지 않고, 어떤 상한선도 고급 사용자를 막지 않는다. ＋만들기 칩과 레이어로 편집 토글, 단 두 개의 문이 두 세계를 잇는다.

지금 FaceMakeup.shader의 _MakeupOverlay는 텍스처 1장(lerp 1회). 그런데 R1(자유 배치)·R6(하이브리드 캐노니컬측)·R8(캐노니컬 순서)·R9(그림 여러 장)이 전부 "얼굴 캔버스에 여러 장 얹기"에 의존한다. 이 경로가 아직 없다 — 요구의 절반이 여기 걸려 있으니, 가장 먼저 이 스파이크(오버레이 N장 합성 실증)부터 뚫어야 한다.

지금 만들 것 · 첫 출시

데이터 모델을 갈아엎기 전에 전용 메시 위에서 가치를 먼저 증명한다: 아이라인 5축 분해(R5) + 명명 워프(R7: 눈꼬리 띄우기). 순수 필드 추가라 하위호환 100%, 기존 프리셋 무손상, 실기기 리스크 최소. 이게 "부품 조합 + 내 얼굴 맞춤"의 첫 손맛.

지금 미루는 것 · 과설계

  • 15→3 uber 셰이더 통합 — 배리언트 폭발 + 실측 튜닝 회귀. 첫 출시엔 기존 셰이더 유지.
  • GrabPass → 프레임당 1회 Blit — 레이어 십수 장 전엔 병목 아님. 색소 누적 타이밍 회귀 위험.
  • 자유변형(FFD)·자유 정점 워프 — 명명 핸들로 가치의 80%. 자유 드래그는 최후.
정직한 평가

골격은 견고하다 — R7 워프 = 기존 browThickness/browArch의 일반화, R5 5축 = 직교 머티리얼 프로퍼티, 리치 모델은 RN에만·브리지엔 컴파일된 커맨드만. R2·R3·R5·R7(전용메시)·R8은 기존 자산 위에서 무리 없이 간다. R1·R6(캐노니컬측)·R9는 위 블로커 하나에 걸려 있다. 그래서 첫 삽은 전용메시 축분해 + 명명워프로 좁히는 게 옳다.

접착 — 미끄러짐·떠보임 잡기

"얼굴에 딱 붙어 같이 휘게"는 이 코드가 이미 두 불변식으로 보장하고 있고, 새 레이어는 그걸 공짜로 상속합니다.

불변식 1시간 동기

배경을 ARCameraBackground(최신)가 아니라 MediaPipe가 랜드마크를 계산한 바로 그 프레임으로 그린다(FramePresenter). 영상·랜드마크가 같은 시각이라 원리적으로 어긋날 수 없음.

불변식 2단일 매핑

배경·얼굴 메시·립·홍채가 전부 같은 ImageToViewport 변환을 공유. displayMatrix 추측이 없어 어긋남 불가.

공짜 상속_source.Landmarks만 읽으면 끝

Landmarks는 이미 지연재생 + One Euro(정지) + raw-pin(움직임) + 속도/발산 게이트를 통과한 값. 새 메시/데칼은 이걸 읽기만 하면 접착을 무료 상속 — 스무딩·핀 재구현 금지. 정점 위치 EMA 금지(움직임 지연 유발).

R7 워프가 접착을 깨지 않으려면 — 정규화 좌표(픽셀 아님), 로컬 프레임(iso)에서 방향, 파라미터만 EMA(정점 위치는 raw-pin 그대로), 방향 기준은 개폐/회전에 안정적인 랜드마크(눈 감을 때 뒤집히는 홍채 중심 대신 눈썹 하단).

왜 메시 케이지(a)가 아니라

  • 윤곽/턱 슬림이 불가 — 실루엣을 안으로 당기려면 원래 얼굴 자리에 배경을 채워야 하는데, 얼굴 메시 정점엔 그 바깥 데이터가 없음.

스크린공간 변위(b)

  • 각 출력 픽셀이 원본 어디를 읽을지 역방향 필드로. 눈확대=홍채중심 방사 스케일, 슬림=윤곽선 법선 밀기.
  • 배경 쿼드 셰이더만 교체 → GrabPass 소비자(메이크업 6셰이더)는 자동으로 보정된 픽셀 위에서 동작.
  • RT 프리패스 불필요(GrabPass가 이미 화면픽셀 소비) — 로드맵의 "RT 워프"는 이 구조엔 과설계.
정합 핵심

워프는 화면픽셀을 옮기지만 메이크업 메시 정점은 원본 랜드마크에 남음 → 눈을 키우면 아이라이너가 커진 눈 안에 작게 뜬다. 해법: 같은 필드의 순방향(p_orig → center + (p−center)·scale)을 공유 FaceWarpField로 만들어, 각 랜드마크 렌더러의 좌표 헬퍼에 한 줄 삽입. 정직히: 이 "한 줄"이 IrisRenderer·LipRenderer·StyleRenderer·BrowRenderer·CanonicalFaceMesh 5개 파일에 들어가야 한다(배경은 무변경이지만 랜드마크 정합은 5곳 침습).

배경 왜곡(눈확대가 주변 배경도 늘림): 반경을 눈폭 1.3배로 타이트하게(smoothstep 경계에서 변위·1차도함수 0) + 얼굴 메시 스텐실 마스크로 얼굴 밖 변위 0. 윤곽슬림은 역방향이라 배경이 늘지 않고 얼굴이 배경을 덜 가림 → 자연 처리.

전 부위 일반화 — 3종 오퍼레이터

눈·윤곽만이 아니라 코·입·이마·볼·눈꼬리까지 — "뷰티캠"의 모든 조정을 3종 워프 오퍼레이터의 합성으로 연다. 각 슬라이더 = 오퍼레이터 {type, anchor(랜드마크 그룹), strength, radius, falloff} 하나. 필드 = 활성 오퍼레이터들의 합성이며, 배경 쿼드는 그 역방향(픽셀 읽기)·메이크업은 순방향(정점 이동)으로 같은 필드를 공유.

14

머리카락 인식

1차 소스 = 오클루전용으로 설계한 SelfieMulticlass의 hair 채널(같은 링버퍼·같은 ts, 추가 비용 0). 여는 것: 앞머리 오클루전(이마·눈썹 가린 픽셀 제외) · 헤어라인 마스크(베이스가 머리카락에 안 발림) · 경계 페더.

치명적 함정눈썹 화이트리스트

세그 hair 채널이 짙은 눈썹을 머리카락으로 오분류 → 오클루전이 눈썹 메이크업을 통째로 지움. 대책: 최종 = hair AND NOT 눈썹밴드. 이미 있는 BrowRenderer 밴드를 감산(신규 자산 0).

우아한 저하세그 없을 때

세그 미탑재 빌드는 얼굴 메시 경계 게이트만으로 폴백(메시 밖=안 칠함). 이마로 내려온 앞머리만 세그 필수 — 그건 있을 때만 곱연산.

정직한 비용좌표 정합

"정규화 UV 샘플 한 줄"은 과소묘사 — 검출(640)↔표시↔스크린 UV 변환 정합이 실제 작업. 세그 파이프라인 자체가 아직 미구현.

15

눈썹 삐져나옴 — 리셰이프/컨실

"의도한 모양 밖으로 자연 눈썹이 삐져나옴" = 새 눈썹 밴드 밖의 자연 털을 피부톤으로 지우는 것. 실제 화장의 "눈썹 정리 후 그리기"와 같다. 커버 영역 = 자연눈썹 ∩ ¬(새 눈썹 모양).

BrowConceal (+4 신설)

BrowLightener(이미 "어두운 털→이마 피부톤 커버")를 넓은 밴드에 복제하고 (1 − 새눈썹모양) 구멍 한 항을 더한 것. 스택: +4 컨실(넓게) → +5 라이트너 → … → +9 새 눈썹. 큐 순서로 "지우고 그 위에 그리기" 자동.

검출기존 루마 게이트 재사용

라이트너의 GrabPass 루마 게이트(픽셀 정확)를 넓은 밴드로 공간 한정 → 안경테·볼 그림자 오검출 차단. 셰이핑(_thickness/_arch)은 반영 안 함(반영하면 삐친 털을 또 놓침). 세그 hair 채널은 눈썹 전용 클래스가 없어 보류.

정직한 규모최소 디프는 아님

"한 항 추가"지만 실제론 넓은 전용 밴드 메시 + 새 눈썹 모양을 정점 채널(TEXCOORD1)에 구워 protect 구멍을 만드는 지오메트리 작업이 필요. BrowRenderer 셰이핑식을 컨실과 공유(중복 구현 금지)해야 밑동 자국이 안 남음.

밴드형(눈썹·아이라인·립)은 지금 바로 에셋화. 그러나 캐노니컬 마스크·데칼을 여러 부위 얹으려면 섹션 07 "N장 합성 블로커"가 선행(_MakeupOverlay 1장 → N장). 범용 에셋 야심의 절반이 이 게이트.

디자이너 GUI — 로컬 웹

디자이너가 좌표·포맷 실수 없이 "쉽게 집어넣는" 파이프라인. 그리기는 각자 프로툴(Procreate·PS), GUI는 가이드 제공 + 정합 프리뷰 + 검증 + 발행. 웹앱(설치 0, Mac/윈도/아이패드 브라우저).

1

부위 선택 → 가이드

그 부위의 가이드 템플릿(랜드마크·registration 마크) 자동 로드.

2

임포트 / 내장 브러시

PNG 드래그, 또는 마스크는 GUI 브러시로 바로 존 페인팅.

3

얼굴 위 프리뷰

디바이스와 같은 블렌드/틴트 공식으로 실제 얼굴 샘플 위 WYSIWYG.

4

검증 → 발행

해상도·정합·투명비율·색공간 린트 → 통과만 매니페스트와 함께 카탈로그로.

전제 인프라 · P0

좌표 가이드 표준화 — 지금 templates/ 3종을 전 부위로(registration 마크 + 랜드마크 오버레이 + safe margin). 디자이너 GUI·에셋 정합의 공통 전제. GUI↔디바이스 프리뷰 패리티(블렌드·luma-key 공식 공유)와 에셋 린트 자동화가 품질 게이트. 얼굴 전면 에셋이 늘수록 오클루전 마스크(섹션 11)가 실질 전제가 된다.
